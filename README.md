## 沪日专线是什么意思

一句话：沪日专线是IPLC里方向为“上海↔日本”的一条线路。IPLC全称 International Private Leased Circuit（国际私用出租线路），指用户专用的跨国点对点通信线路，可以理解成一条只给你用的、跨海的“网线”。

这类线路按两端城市命名：深港是深圳到香港，广港是广州到香港，苏日是苏州到日本，沪美、沪韩同理。沪日（以及苏日）主要服务华东用户，入口离得近，延迟自然低。

和普通出国线路相比，它有三个结构性区别：

- **点对点独享**：两端之间是专用信道，不和其他用户共用物理链路
- **不过公网**：数据不进公共互联网的国际出口排队，也就是常说的“不过墙”
- **内网通讯**：出口IP不存在“被墙不能用”的问题

不过别把“不过墙”理解过头了。专线只覆盖两端之间的那一段，从你家到国内入口这一截还是普通公网，该有的审查一样有，所以专线谈不上绝对安全。

## 为什么沪日专线能做到25ms延迟

两个原因叠加：物理距离短，中间没有排队环节。

打个比方：用普通VPS出国，像早高峰挤地铁，所有人抢同一条公网国际出口，晚高峰一堵谁都跑不快；沪日专线相当于单独租了一条从上海通到日本的信道，这条道只有你在走。实际部署上，专线走的是运营商之间的陆缆或海缆，和公网流量物理隔离。

具体到商家，实现细节有差别。MKCloud的沪日IPLC走APG海缆，日本端接入PCCWG、NTT、Cogent等多家运营商，还对接了到Google、Cloudflare的私有PNI；CloudIPLC则是上海BGP入口、日本NTT/BBIX出口。

从公开数据看，沪日IPLC端到端延迟普遍在25–40ms之间：MKCloud标称端内25ms，CloudIPLC标称26ms，华纳云在一篇IPLC介绍里给的参考值是40ms左右。玩日服游戏的话，25ms基本是感觉不到的水平。
